## Observable by a package

| # | mechanism | GNU | romacs | why |
|---|---|---|---|---|
| VM2-LOADCOMPILED | Which loads run compiled code | GNU's `load` picks a file's `.elc` (or `.eln`) by its suffix rules; an installation ships its Lisp compiled by `make`, and a package's `.elc` is made when it is installed. | In an interactive session (by default; `ROMACS_COMPILED_LISP=off` turns it off) and in a batch run with `ROMACS_COMPILED_LISP=on`, a load of a library by its name runs a compiled-Lisp artifact, whether or not GNU would satisfy it with compiled code: a file of the installation's Lisp trees, or one beside an `.elc` that `load-prefer-newer` accepts, as GNU does, and also a user's package or any library on `load-path` with no `.elc`, which GNU's `load` interprets but package.el compiles when it installs a package (a `load` that names the `.el` still reads source). Such a library then runs compiled semantics, as a package GNU installed does: a `let` of a variable its file declares only later binds lexically, and what `eval-when-compile` loads is not loaded at run time. The artifact is the file walked by bytecomp's file rules in a compile process, each top-level form compiled to VM2 code, and the units run in order under GNU's compiled-load bindings and unwind (`crates/romacs-vm/src/compiled_lisp`). A load with no artifact reads source in an interactive session, which compiles the file in the background later (VM2-LOADPRECOMPILE), so no load waits for a compile; a batch run compiles it synchronously, then loads it. An installer compiles the installation's trees ahead of use, as `make` does GNU's (`romacs-vm-gui --compile-lisp-tree`, `compiled_lisp::tree`), so a session's first load of a shipped library finds its artifact. A compile loads a file being compiled up its own chain from source, whatever the store holds, so what it makes never depends on which compile published first. A session without a store of its own (a fresh HOME's batch run) uses what is compiled and reads the rest from source, compiling nothing. Artifacts are never stale: every observed input (files loaded and resolved at compile time, host reads, inherited environment variables) is checked again at load, and a change recompiles. | GNU runs a stale `.elc` with a warning; here a changed source or dependency always recompiles. A user's libraries are compiled as their installed form would be, so a session never reads a package or an init's library from source again once it has loaded it. With compiled loads, VM2-EWCLOAD1 applies to source-kind loads only. | <!-- symbols: load, require, load-prefer-newer -->
