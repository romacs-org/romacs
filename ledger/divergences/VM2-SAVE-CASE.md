| VM2-SAVE-CASE | Actual filesystem case sensitivity | `fileio.c:2647` answers from the platform: nil on GNU/Linux, where no `_PC_CASE_*` pathconf exists, without asking the filesystem; t on MS-Windows and Cygwin; macOS asks `pathconf (_PC_CASE_SENSITIVE)`, walking up while it cannot tell. Handlers run first. | Handlers run first. On Linux Romacs measures where GNU assumes nil: from the name's directory (the name itself when it is a directory, else the directory it is in, walking up to the nearest that exists), one `statfs` reads the filesystem type. vfat and msdos (`MSDOS_SUPER_MAGIC` 0x4d44), exFAT (0x2011bab0), the old ntfs driver (0x5346544e, case-insensitive unless mounted `case_sensitive=yes`), HFS (0x4244) and HFS+ (0x482b) answer t; an HFSX volume, which may be case-sensitive, answers t as well. On ext2/3/4 (0xef53), f2fs (0xf2f52010) and tmpfs (0x01021994), one `FS_IOC_GETFLAGS` on the directory, opened `O_DIRECTORY` and `O_NOFOLLOW`, answers t when `FS_CASEFOLD_FL` is set. Every other filesystem answers nil, among them ntfs3 (case-sensitive unless mounted `nocase`, which statfs cannot show), CIFS and SMB2 (the server and mount options decide) and FUSE. Any error answers nil, as GNU does when it cannot tell; nothing signals for an unknown answer, and no directory is listed, so a directory's size never matters. A world build records the walk's entry types (not their times), the filesystem type and the flags as keyed probes, and restore asks them again; its confined thread reads flags through an unconfined thread that makes only that query. A unibyte non-ASCII name (ENCODE_FILE's output, which `set-auto-coding` passes on) names the file its UTF-8 bytes spell; other bytes are refused. Off Linux: t on MS-Windows, else nil (no macOS pathconf). | Deliberate Romacs choice: the answer is measured on the filesystem, not a platform constant. The earlier directory-entry measurement signalled for a directory over 4096 entries and broke startup from a large working, home or temporary directory. Qualified for real only on a casefold tmpfs made in a private user and mount namespace (`filename_case_measures_a_real_casefold_directory`, `crates/romacs-vm/tests/savejourney.rs`); no real vfat, exFAT, NTFS, HFS, ext4 or f2fs casefold mount has been qualified, and those answers rest on the magic numbers and the classifier's unit tests (`savejourney.rs` `case_tests`).
