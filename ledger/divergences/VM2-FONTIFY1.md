| VM2-FONTIFY1 | Redisplay runs `fontification-functions` once per unfontified stretch | GNU `handle_fontified_prop` (`src/xdisp.c:4667`) runs wherever the display iterator stops on text whose `fontified` char property is nil: at property and overlay boundaries, at most `TEXT_PROP_DISTANCE_LIMIT` (100) characters apart, and again on every iterator pass, so a function that leaves `fontified` nil is called at each later stop. Every iterator user fontifies (`vertical-motion`, `pos-visible-in-window-p`, `window-text-pixel-size`, ...), and `redisplay-skip-fontification-on-input`, `inhibit-eval-during-redisplay`, long-line narrowing and the nested-redisplay abort apply | Each window's redisplay calls `romacs--redisplay-fontify` (rlisp/vm/prelude.el) over the rows it shows, window start through the end of its last row: over the host's layout, the rows painting lays out (VM2-RD1), and before the window's first paint screen lines as the display iterator counts them, or logical lines where it refuses the text. The functions run at the first position of each maximal nil-`fontified` stretch, under GNU's `dsafe_call1` rules: `inhibit-redisplay` bound, `fontification-functions` bound to nil, a buffer-local `t` running the global functions, and a signal logged as `Error during redisplay: (FN POS) signaled ERR` that never ends redisplay. The property is then read again, and the walk ends at the end it began with.
