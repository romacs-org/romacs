| LISP-TREESIT-FONTIFY | Who applies a tree-sitter font-lock setting's captures to the text | `treesit--font-lock-fontify-region-1` gets the captures as a list from `treesit-query-capture` and walks it in Lisp, writing each face with `treesit-fontify-with-override` and calling each function capture (`treesit.el`). | `lisp/romacs-treesit-font-lock.el`, loaded after every load of treesit.el, defines `treesit-font-lock-fontify-region` and `treesit--font-lock-fontify-region-1` again. Consecutive enabled settings of one language are one query (`romacs--treesit-query-combine`, kept until the settings or their enable flags change), so a region is walked once per language, not once per setting; `romacs--treesit-fontify` runs its captures and, setting by setting, each setting's predicates and then, in the same order, writes the same faces (`put-text-property`, or `treesit-fontify-with-override` for an override other than nil or t) and calls the same functions with the same arguments; no capture list is made. `#pred?` predicates run inside the `with-silent-modifications` the faces are written in; GNU runs them before it. With several root nodes of one language (fast mode's subtrees, which do not overlap), a node's settings are applied before the next node's, where GNU applies one setting to every node before the next setting.
