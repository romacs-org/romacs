| VM2-FILESPECIAL1 | A file-local `(defvar x)` reaches the rest of its file only when it is a bare top-level form | `Fdefvar` with one argument (`src/eval.c:990-996`) conses SYMBOL onto `internal-interpreter-environment` when that is non-nil; `readevalloop` (`src/lread.c`) binds the variable once for the whole file and evaluates each form with `eval_sub`, which does not rebind it, so the declaration makes SYMBOL dynamically bound by every LATER `let` and closure of that file and of no other file. A `progn`, `when` or binding-less `let` around it does not rebind the environment either, so `(progn (defvar x))`, `(when t (defvar x))` and `(let () (defvar x))` at top level all persist; `(when nil (defvar x))` does not run and declares nothing. Live GNU 32.0.50: `crates/romacs-vm/evidence/file-local-special/` (`gnu-transcript.txt`, `nested-forms.txt`) | VM2's loader records a top-level form that is exactly `(defvar SYMBOL)` once it has evaluated, and seeds the root compilation of every later form of the same file with those names (`crates/romacs-vm/src/loader.rs`); it also conses the name onto the file's binding of `macroexp--dynvars`, as GNU's `macroexpand--all-toplevel` does, so a macro that evaluates code at expansion time (`eval-and-compile` inside `pcase-defmacro`) hands the declaration to `eval`, saving and restoring the set around each `load`; the source cache keys its validity on them, so an identical form in a file without the declaration is recompiled. A declaration nested inside a top-level `progn`/`when`/`let` still reaches only the rest of its own form (the compiler's existing local-special scope, VM2-VD1), so GNU's `(1 2 3 unbound)` for the four nested shapes above is VM2's `(unbound unbound unbound unbound)` past the form. `eval-buffer`/`eval-region` are not covered. Before this row (fixed on `vm2/defvar-local`) even the bare form reached nothing past itself, which made cl-macs.el's `(defvar cl--loop-args)` (line 939) ineffective. The source caches (in memory and persistent) key a cached form on each name's declaration KIND, lexical / file-local / global (`Vm::special_kind`), and the persistent cache's portable compiler reproduces file-local declarations as file-local (Sol review of af1209d0: it had made them global, so a warm load bound a lambda parameter dynamically where the cold load bound it lexically; `tests/file_local_special.rs`).
