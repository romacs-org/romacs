| VM2-UNDO-OUTER | When a collection truncates an undo list and asks `undo-outer-limit-function` | `undo.c:290` `truncate_undo_list`, from `alloc.c:5688`, first in every `garbage_collect`, before marking and so also when the user then quits: the function is called there, inside whatever allocated, with collection inhibited, and the cut is made on its answer. A signal from it leaves the collection | A mark decides the cuts after its main drain and makes them after its last key poll, so that an idle collection a key press abandons leaves every list as it was. Collection is not inhibited, but a collection inside the function asks it nothing; a list circular with no boundary ends the walks, where GNU's does not end. Two consequences of asking afterwards. Each buffer is asked about as it stands when its turn comes, so one the
function already dealt with while answering for another is not asked about. And a function that signals leaves the
list as it is and the buffer counted as looked at: it is asked again once the buffer changes, where GNU asks at the
next collection. A run asks about a buffer once: one the function puts past the limit again while it
answers for another waits for the next collection.
