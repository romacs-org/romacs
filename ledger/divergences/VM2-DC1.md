## Observable by a package

| # | mechanism | GNU | romacs | why |
|---|---|---|---|---|
| VM2-DC1 | `defcustom` stores the raw default form where GNU stores a thunk, and `:set` is never invoked | Measured on GNU 32.0.50 for `(defcustom e-opt (progn (setq n (1+ n)) 7) "d" :type 'integer)`: `(get 'e-opt 'standard-value)` is `((funcall #'#[nil ((progn (setq n (1+ n)) 7)) (t)]))` — a list whose car is a **form that calls a closure** wrapping the default — so `(eval (car (get 'e-opt 'standard-value)) t)` returns `7` and re-runs the side effect. A `:set` function runs **once at definition**. `custom-variable-p` answers non-nil | VM2 stores the **raw unevaluated form**: `standard-value` is `((progn (setq n (1+ n)) 7))`. `(eval (car (get 'e-opt 'standard-value)) t)` **signals `void or non-function`** rather than returning 7, and the side effect does not re-run. A `:set` function is recorded under `custom-set` but **never invoked** — the setter counter stays 0 where GNU's reaches 1. `custom-type` and the other keyword properties match GNU, and **`custom-variable-p` matches GNU exactly** (`t` for a `defcustom`-defined symbol, `nil` otherwise). No theme machinery (removed by R90) | **Package-observable** in two ways. Code that recomputes a default via `(eval (car (get 'sym 'standard-value)) t)` — which is what Custom itself does — gets an error instead of the value. Code relying on `:set` running at definition time silently does not get its setter called, so a variable whose setter has side effects beyond `set-default` is left uninitialised. Ordinary reads of the variable's value are identical, and `custom-variable-p` is not a difference. Revertible: wrap the stored form so `eval` of the car yields the default, and invoke `custom-set` at definition | <!-- symbols: defcustom, standard-value, custom-set, custom-type, custom-variable-p -->
