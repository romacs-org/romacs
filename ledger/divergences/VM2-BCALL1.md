## Observable by a package

| ID | Area | GNU behavior | Romacs behavior |
| --- | --- | --- | --- |
| VM2-BCALL1 | Every named call compiled by Romacs (all Lisp is compiled: `eval`, `load`, `ielm`) evaluates its arguments, then reads the function cell. | GNU's byte code does the same (`src/bytecode.c:758-829` `Bcall`: `call_args` are on the stack before `call_fun = XBARE_SYMBOL (call_fun)->u.s.function`); GNU's interpreter (`eval_sub`) reads the cell first. Pinned GNU 32.0.50, byte-compiled `(f (progn (fset 'f g) 1) 2)` calls `g`; `(undefined-fn (progn (setq zz 1) 2))` signals `void-function` with `zz` = 1; interpreted, `f` and no assignment. | A redefinition, `advice-add` or `cl-letf` made while an argument runs is seen by that very call, and `void-function` for an unbound head is signalled after the arguments ran. A redefinition made before the call is always seen at the call (the site cache compares the cell's version on every call: `threaded.rs` `direct`, `direct_kernel`, `direct_generic`). One loader-order case is kept: a *top-level* form, or a form deferred to its reach (R215's non-eager regime), whose head has no function when it is compiled (typically a macro from a file not yet loaded) checks the head before its arguments, so a load stopping at `(define-inline …)` reports `(void-function define-inline)` as GNU's loader does, not the void variable its first argument would be; the check runs once per such form and never inside an eagerly compiled function body (there the void variable is reported first, as compiled GNU does). | The compiled order is the one GNU packages are byte-compiled against; it costs one load-compare per call where the interpreter order needed a separate resolution instruction and a traced snapshot register per call (`named-call-1` micro and ERT/census measurements in the commit). Tests: `tests/call_heads.rs` `named_call_reads_the_cell_after_its_arguments`, `tests/oclosure.rs`. | <!-- symbols: fset, defalias, advice-add, cl-letf, void-function, funcall -->
