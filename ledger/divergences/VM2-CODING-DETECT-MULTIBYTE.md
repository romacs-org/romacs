## Observable by a package: coding detection of multibyte text

| # | mechanism | GNU | romacs | why |
|---|---|---|---|---|
| VM2-CODING-DETECT-MULTIBYTE | what coding detection reads of multibyte text | GNU's detectors read a multibyte source's raw bytes (eight-bit characters) as those bytes and any other character as a non-byte (`ONE_MORE_BYTE` in coding.c), which no single-byte or multibyte coding's byte pattern matches | Romacs reads a raw byte as itself and any other character as its internal UTF-8 bytes (`coding_detection_bytes`, `crates/romacs-vm/src/prim/leaf/coding.rs`), so a character can count for a coding's byte pattern. With pinned GNU 32.0.50 and Romacs, `(detect-coding-string S t)` agrees on ASCII, on `"café"`, on raw bytes alone and on ISO-2022 escapes, but `"café"` followed by the raw byte `\351` is `iso-latin-1` in GNU and `utf-8` in Romacs, and the candidate lists of the full call differ for non-ASCII text | Detection reads the buffer's text as one byte sequence, which Romacs holds as UTF-8 with raw bytes kept apart; multibyte text mixing characters and raw bytes is rare, and file visits detect on the file's bytes, before any decoding | <!-- symbols: detect-coding-string, detect-coding-region -->
