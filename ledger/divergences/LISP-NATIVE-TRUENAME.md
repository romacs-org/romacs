## Observable by a package

| # | mechanism | GNU | romacs | why |
|---|---|---|---|---|
| LISP-NATIVE-TRUENAME | How `file-truename` walks a local name | GNU's Lisp (`lisp/files.el`) recurses over each directory level of the name, asking `find-file-name-handler` and `file-symlink-p` at each level, splicing each link's target in and starting again, with a budget of 100 steps (COUNTER) and a cache of directory true names (PREV-DIRS) | On the outermost call, with no handler for the name made absolute (a relative name joined to `default-directory`, which is expanded only when it does not begin with a slash), the primitive `romacs--file-truename-local` (`crates/romacs-vm/src/prims/truename.rs`) walks the name's components once, asking each joined name for its link target (readlink) and resolving `.` and `..` against the true name so far, as GNU's levels do. A walk that follows more than 3 links or runs deeper than 20 components returns nil, and GNU's algorithm (`file-truename--walk`) decides the name, errors and messages included; COUNTER or PREV-DIRS given select it too, and so does a true name, reached through a link, that a handler claims. `test/romacs/lisp/file-truename-tests.el` | **Package-observable:** a file name handler is asked once for the whole name, not once per directory level, so a handler whose regexp matches only a directory part of a local name (none in Emacs's own handlers) is not asked. Answers are pinned GNU's on the test's tree: links absolute and relative, `..` after a link, a trailing slash, `.` and doubled slashes, a missing tail, a relative name, a loop.
