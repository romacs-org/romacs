| VM2-TERM-KEYS | Keys in `romacs-term` | GNU's `term` in char mode binds every key in `term-raw-map` to `term-send-raw` but its escape character (C-c), and sends from the command loop; its line mode edits the line in the buffer. vterm and eat send from their mode maps too, less an exception list (`vterm-keymap-exceptions`). | Every key goes through the command loop. While a window shows the terminal with point on its cursor, a generated keymap sends each key's xterm bytes (`romacs--term-send-event`, `terminal_keys.rs`), except `romacs-term-keymap-exceptions` (C-c C-x C-u C-g C-h C-l M-x M-o C-y M-y C-v M-v), which keep their Emacs bindings; on the alternate screen only `romacs-term-alternate-exceptions` (C-x M-x C-g) do. The keymap is the buffer's local map for one key sequence, chosen when its first event is read (`romacs--sequence-start-functions`) and only over `romacs-term-mode-map`, so a prefix keeps its route whatever arrives before its next key, minor modes and overriding maps come first (as vterm's local map), a local map another installs (a confirmation's answers) is kept, and `romacs-term-mode-map` bindings win over the sent keys. A command that moves a window's point off the cursor, or its start off the grid, leaves that window a plain read-only buffer that output does not move (`terminal_host.rs` `terminal_track`); typing there puts it back on the cursor and sends the key. C-y sends `current-kill` as Alacritty pastes (bracketed and less ESC and ETX when the program asks, else with line ends as RET); M-y chooses a kill and sends it, replacing nothing; C-c C-c and C-c C-k send ETX. Escape reaches every buffer as the function key `escape`, made ESC by `function-key-map` where unbound, as GNU's X frames deliver it. In the workspace (no GNU Lisp), whose key lookup has only local and global maps, C-u's digits reach the program. `tests/terminal_mode.rs`, `tests/terminal_loadup.rs`, `tests/terminal_host.rs`, `tests/terminal_keys_parity.rs`; `harness/terminal_live.py`; `harness/terminal_latency_live.py` | **User-observable**: a terminal is one buffer, with no line or char mode; a package sees `romacs-term-mode-map`, the exception lists and the per-sequence local map. A plain passthrough key (one the command loop would only send) is written by the host after a native lookup through the same keymaps in GNU's precedence (`terminal_host.rs` `terminal_passthrough_key`), without the command loop: global `pre-command-hook` and `post-command-hook` do not run for it, nor do `this-command`, `last-command-event` or `recent-keys` change, since its effect is in the pty, not the buffer (vterm and eat run Lisp per key); a buffer-local command hook, a keyboard macro, an input method, an overriding, emulation, minor-mode or text-property map that binds the key, or a remapping sends it through the loop. Measured (`harness/terminal_latency_live.py`, `--loadup`, 5 pairs of 250 keys): ingress to the byte in the pty about 0.05 ms slower at p50 than the host router it replaces (0.37 against 0.42 ms, base spread 46%), no added frame; the native check costs about 3 us hot but about 50 us in a session, where each key, 30 ms after the last, finds its keymaps and variables out of cache. | One mode with Emacs keys everywhere (vterm's model) and the user's keymaps honoured; the host router it replaces sent keys before any keymap saw them. | <!-- symbols: romacs-term, romacs-term-mode-map, romacs-term-keymap-exceptions, romacs-term-alternate-exceptions, romacs-term-update-keymaps -->
