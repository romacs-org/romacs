| VM2-SAVE-LOCK | Native locking protocol and lifecycle | GNU uses symlink interlocks, local PID/boot checks and automatic edit/save lifecycle locking. | `lock-file` and `unlock-file` dispatch their handlers and implement symlink interlocks, stale removal and conflict callbacks; a buffer's first modification locks its truename (`rlisp/vm/insdel.el`), `restore-buffer-modified-p` and `set-buffer-modified-p` lock or unlock it as the state flips, `kill-buffer` unlocks a modified buffer's file, `kill-emacs` unlocks every modified buffer's (unlock_all_files), `write-region` locks LOCKNAME before writing and unlocks it after (but for an auto-save), and a visit unlocks the truename and the name, as GNU does. Where GNU's C calls `Flock_file` or `Funlock_file` directly, Romacs calls `lock-file` or `unlock-file` as Lisp functions, so advice on them applies. Before files.el defines `make-lock-file-name` (the bare regime) a file has no lock name. Some nested callback errors propagate instead of redirecting to unlock error handling. Nonregular lock files refuse, link-less filesystem fallback and cross-host boot databases are absent. The boot field is omitted (GNU-supported legacy identity) because `/proc/stat` differs from GNU gnulib boot time on this host; live local PID locks are conservatively retained regardless of the supplied boot field. Reboot/PID-reuse stale detection is therefore unimplemented and may report a false conflict instead of deleting a live owner. Current login environment supplies identity; subsequent changes may affect it. | Explicit native locking slice, not full lifecycle parity. `crates/romacs-vm/evidence/filelock-save/REPORT.md`. |
