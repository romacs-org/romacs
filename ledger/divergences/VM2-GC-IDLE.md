## VM2 explicit garbage collection

| # | Mechanism | GNU | Romacs | Why |
|---|---|---|---|---|
| VM2-GC-IDLE | Collection while the command loop is idle | `read_char` (`keyboard.c:2984`) calls `maybe_gc` only after its idle auto-save wait (`auto-save-timeout`, 30 s or more, and only after input since the last auto-save) with no input pending, and that collects only when the automatic trigger is already due. `garbage-collect-maybe` (`alloc.c:6110`) collects once more than 1/FACTOR of the trigger's allocation happened. | The GUI's command loop, on an idle pass where no process output, timer or auto-save ran and no message waits to be shown, asks `romacs--idle-collect` (`rlisp/vm/keyboard.el`): once idle `romacs-gc-idle-delay` seconds (2; nil turns it off) with no input pending and more than 1/`romacs-gc-idle-factor` (4) of the way to an automatic collection (`romacs--collection-share`: the larger of the objects allocated over their trigger, VM2-GC-PACING, and the request code compiled over the request boundary's threshold), the host collects after the idle pass returns. Below that share nothing is scheduled, so a quiet session never wakes for it. `gcs-done` then grows while no command runs. A prompt's key wait runs in Lisp (`romacs--read-char`) and collects by `romacs--collect-idle`, which gives way to a key press while it marks. Batch sessions have no idle loop and are unchanged. `garbage-collect-maybe` uses the object trigger alone: request code retires only at a request boundary, which Lisp never is. | A Romacs collection traces and moves the whole heap, compiled code included, so each one stalls the session for tens to hundreds of milliseconds, and in a session most are due to request code (a quarter of the installed functions compiled since the last collection), not to `gc-cons-threshold`. Collecting at idle moves those stalls off commands. The host makes the collection outside any request, where request code retires; a collection from Lisp inside the idle pass would keep it. On the general-usage bench replay (94 compared steps, 2.5 s after each key step, development machine under load), collections during commands went from 9 (3.28 s in all, the longest 1.27 s) to 6 (1.47 s, the longest 0.63 s), with 18 more at idle (4.77 s, the longest 0.52 s); median RSS from 994 MB to 784 MB; no step's verdict changed. Tests: `timers::tests::idle_collects_after_its_delay_once_enough_was_allocated` (`crates/romacs-vm-gui/src/timers.rs`), `collection_counters_and_garbage_collect_maybe` (`crates/romacs-vm/tests/garbage_collect.rs`, GNU-compared). | <!-- symbols: garbage-collect-maybe, gcs-done, gc-elapsed -->
