| VM2-PATH2 | `default-directory` and `expand-file-name` | `default-directory` is a per-buffer C variable, always local and permanent (`src/buffer.c:5426`, index -1): a new buffer copies the current buffer's (`reset_buffer`, `buffer.c:1093`), the first buffer gets the process directory with a trailing slash (`init_buffer`, `buffer.c:4969-5017`), `kill-all-local-variables` keeps it and a `let` of it binds the current buffer's value. `expand-file-name` (`src/fileio.c:994-1765`) reads it when DEFAULT-DIRECTORY is nil, expands a relative or `~` one against `invocation-directory`, falls back to `/`, calls the `expand-file-name` handler of NAME, of the directory and of the result, and keeps a trailing slash, a leading `//`, `..` above the root and an unknown `~user`; every file primitive expands its names through it, and `openp` (`src/lread.c:1756`) expands each PATH element and then, for a still-relative result, against the buffer's directory | VM2 now models the variable as GNU's (`crates/romacs-vm/src/forwarded.rs`, `buffer.rs` `create_named_buffer`) and ports `Fexpand_file_name` as a T2 state machine (`crates/romacs-vm/src/prims/expand_file_name.rs`): each handler call and each recursive expansion is a Lisp call, and the file primitives run the same machine natively, continuing through Lisp `expand-file-name` only where GNU would call a handler (`file-exists-p`, `file-readable-p`, `file-executable-p`, `file-writable-p`, `file-regular-p`, `file-directory-p`, `file-modes`, `set-file-modes`, `set-file-times`, `delete-file`, `delete-file-internal`, `delete-directory-internal`, `make-directory-internal` and `locate-file-internal`; `file-directory-p`, `file-regular-p`, `file-modes` and `delete-directory-internal` also call a `directory-file-name` handler), so a `/:`-quoted directory reaches `file-name-non-special` as in GNU (`executable-find` binds one). Every other file primitive that expands a name (`insert-file-contents`, `write-region`, `copy-file`, `rename-file`, `add-name-to-file`, `make-symbolic-link`, `directory-files`, `directory-files-and-attributes`, `file-attributes`, `file-symlink-p`, `file-accessible-directory-p`, `file-name-all-completions`, `file-name-completion`, `file-name-case-insensitive-p`, `file-system-info`, `file-newer-than-file-p`, `access-file`, `get-file-buffer`, the visited-modtime and lock primitives, `sqlite-open`) does the same, and then calls its own operation's handler as GNU does (`tests/real_ert_load.rs` `file_name_handlers_match_gnu` compares each one's handler calls with pinned GNU's, tramp's completion handler for names such as `/home` among them). Differences that remain: `load` resolves a nil or relative `load-path` element against the process directory, not `default-directory` (measured: `(let ((default-directory D) (load-path '(nil))) (load "f" nil t))` finds `D/f.el` in GNU and signals `file-missing` in VM2); `init_buffer`'s `/:` quoting of a magic process directory never applies because no handler exists when the first buffer is made; a non-ASCII `$HOME` is taken as its bytes, not decoded with the file name coding system; when NAME and the directory are both ASCII but differ in multibyteness the result keeps NAME's, where GNU converts NAME (VM2 reads every string literal as multibyte, so converting would turn ordinary names into unibyte copies no longer EQ to the argument); the first buffer's directory is created decoded (unibyte ASCII, else multibyte UTF-8) because VM2 runs no startup.el to decode `init_buffer`'s unibyte bytes. In the gnu-ert bootstrap regime loaddefs.el is not loaded, so `tramp-mode` is void and `file-name-non-special` signals there; the loadup regime matches GNU (`crates/romacs-vm/tests/real_ert_load.rs` `default_directory_and_expansion_match_gnu`) | **Package-observable, loud:** a handled name (e.g. a `/:` or remote name) given to one of the listed primitives signals instead of being handled; `load` through a nil `load-path` element ignores a bound `default-directory`.
