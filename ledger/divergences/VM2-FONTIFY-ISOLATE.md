## Observable by a package: isolates and frozen values

| # | Scope | GNU | VM2 | Reason / evidence |
|---|---|---|---|---|
| VM2-FONTIFY-ISOLATE | Font Lock of large buffers (`font-lock-fontify-region` under jit-lock) | Redisplay fontifies each chunk it shows in the session, blocking it while Font Lock runs. | A visited buffer of `romacs-fontify-isolate-size` characters or more in a mode of `romacs-fontify-isolate-modes` (Emacs Lisp, C, C++) is snapshotted (`buffer-snapshot`) once the session idles and fontified in a pooled worker of the session's world, which runs the mode on its own copy and walks it with `jit-lock-function` as redisplay would, from the window's start; the worker streams the resulting text properties block by block. While the snapshot is current (`buffer-snapshot-current-p`: text, mode, generation) and the worker's Font Lock setup has the session's fingerprint (keywords as written, region, extension and syntactic-face functions, managed properties, chunk size, the syntax of characters 0-255), checked again at each use, `font-lock-fontify-region` puts the worker's properties on a covered region instead of fontifying it; anywhere else, and for runs whose values are not plain data (keymaps, functions, nested lists), it fontifies as GNU's. An edit drops the results and snapshots again after `romacs-fontify-isolate-delay` idle seconds; a fingerprint mismatch (a user's hook added keywords or changed the syntax table) leaves the buffer to the session. The worker is retired (`isolate-retire`) once its job is done. The worker sees `romacs-fontify-isolate-variables`, not the user's init (VM2-ISOLATE-GLOBALS). `romacs-fontify-isolate` nil disables it. | The properties are those the same jit-lock walk from the same start gives in the session, apart from cc-mode's whitespace-scan caches (`c-in-sws`, `c-is-sws`), which record what a walk happened to scan (test `a_workers_fontification_is_the_sessions`; live harness `crates/romacs-vm-gui/harness/fontify_isolate_live.py`); only where the work runs differs, so a key that scrolls into unfontified text costs the properties' application instead of the fontification. cc-mode's order-dependent type discovery is redone in the worker's later passes, as redisplay would. Design: vm-concurrency note §3.6, M3. | <!-- symbols: font-lock-fontify-region, buffer-snapshot -->
