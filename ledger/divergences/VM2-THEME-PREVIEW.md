## Observable by a package

| # | mechanism | GNU | romacs | why |
|---|---|---|---|---|
| VM2-THEME-PREVIEW | `load-theme`'s prompt | `load-theme` reads a name and loads it; nothing shows until then. | While `romacs-theme-preview` is non-nil, the prompt shows each theme as it is selected, through `enable-theme` and `disable-theme`, so hooks and variable setters run per candidate. The themes enabled before, every face as it stood and what the enable hooks derive are back when the prompt ends, however it ends, and `load-theme` then does what it does in GNU. A candidate is loaded by `load-theme` itself with its confirmation refused, so a theme `custom-safe-themes` would ask about is not read; one that was read stays declared, as a theme loaded with NO-ENABLE does, and what its file did beyond declaring settings stays done. Enabling a candidate replays the `user` theme's settings as any `enable-theme` does, so a variable changed since Customize set it takes that setting again and a cancelled preview does not undo that. The prompt is the `interactive-form` property of `load-theme`; the function is GNU's. | Choosing a theme by name alone is choosing blind, and a switch now costs less than a frame. |
