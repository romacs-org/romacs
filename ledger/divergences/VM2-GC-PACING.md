## VM2 explicit garbage collection

| # | Mechanism | GNU | Romacs | Why |
|---|---|---|---|---|
| VM2-GC-PACING | Collection pacing units and scale | `consing_threshold` (`alloc.c:5740-5809`) collects once the bytes allocated since the last GC exceed max(`gc-cons-threshold`, 80000) or, for a float `gc-cons-percentage` (default 0.1), that fraction of the live heap's bytes plus half the bytes allocated since; a percentage of 2 or more never collects. | The same rule, read live from both variables, with GNU's defaults (800000, 0.1), in Romacs units: allocation counts heap objects at 16 bytes each (a GNU cons) plus the payload bytes made since, and the live heap is what a collection traces: the objects the last collection retained, their vector slots at two to a cons, and the compiled code units it traced. A percentage P defers collection to 10·P traced heaps (`DEFERRAL_SCALE`), with no half-allocation term: GNU's 0.1 collects after one traced heap, gcmh-style 0.2 to 1.0 after 2 to 10, in proportion, up to 18 (`MAX_DEFERRAL`) at 1.8 or more, so no setting reaches GNU's never-collect point. Negative and NaN settings leave the threshold alone. An embedder's `Vm::set_collection_floor` replaces both variables (as GNU's memory-full state replaces them) with the floor rule tests and `--gc-floor` use. | A collection now frees in place, compacts only on request, sweeps eagerly and marks on several threads, so a traced heap costs about what GNU's does or less, and the old scale of 17 (11.3 traced heaps at 0.1, with a 1.8 clamp) only held memory: GNU's own proportion is kept. 18 is the old rule's most, kept so that a large setting still collects. Release builds, `instructions:u` over all threads (any load), warm runs: a long nested load (15M allocating iterations in a `require`d file): scale 17 at trunk 5.74G instructions, 1 collection, peak RSS 368 MB; now 8.54G, 19, 179 MB, 0.165 s collecting on eight threads (0.297 s on one); wall at load 1 0.88 s against now 0.59 s, and GNU 3.00 s, 224 collections, 1.05 s collecting, 59 MB. The `--loadup` bootstrap: 17.18G, 5 collections, 243 MB against 17.80G (+3.6%), 20, 205 MB. A corpus load (`org`, `gnus`, `calc`, `cc-mode`, `eshell`, `dired`, `vc`, `tramp`): 1.87G against 1.88G, no collection in either. The earlier row's census file could not be identified, so the corpus load replaces it. The pause each collection costs: `harness/perfbench/gc-stalls.el`.
