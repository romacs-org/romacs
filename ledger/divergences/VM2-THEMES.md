| VM2-THEMES | The look a session starts in; theme definition | GNU starts with no theme enabled: `custom-enabled-themes` is nil and every face shows its `defface` default (black on white on a window system); a theme is a `deftheme` file of face specs | Every session with Custom (the `--loadup` GUI and `--batch`, and the worlds built from their chain) starts with the stock theme `default` enabled (`custom-enabled-themes` is `(default)`), enabled as the chain's last form (`lisp/romacs/romacs-loadup-bootstrap.el`, `romacs-theme-start`, which loads `etc/themes/default-theme.el` from `data-directory` itself: `load-theme`'s search reads the per-process `custom-theme-directory`, which a world may not hold). `default` starts from Rum and takes its own colours for code, secondary text, prose blocks and the bar, held to the contrast floors; Rum's definition (`etc/themes/romacs-theme-rum.el`) also makes `rum`, Rum exactly: Modus 5.3.0's face table over Rum's palette (`lisp/romacs/romacs-theme-modus.el`), Romacs's own faces over it, compared face for face with pinned GNU's configured Rum (`crates/romacs-vm-gui/tests/romacs-theme-rum-test.el`, fixture `rum-configured.eld`); `lisp/romacs/romacs-startup.el` keeps only the launch font. A Romacs theme is one palette of base colours (`lisp/romacs/romacs-theme.el` `romacs-theme-define`): the other slots are derived in Oklab (`romacs-theme-rules`, colours as GNU color.el computes them) and `romacs-theme-faces` makes every face of it, each text colour floored to a contrast ratio; the theme is GNU's `deftheme`, enabled and disabled as any other, and sets colours, not the font. `def-romacs-theme` writes such a theme from a short palette, and `etc/themes` ships Romacs's own colour schemes: ten upstream families ported with Romacs's face mapping, every Omarchy palette, `default`, `rum` and `system`. GNU's bundled colour themes and `modus-themes.el` are not shipped, so `custom-available-themes` does not list them and `(load-theme 'tango)` signals unless the user installs one (a package, or a copy in `custom-theme-directory`); `newcomers-presets`, which sets options, stays. Modus lends its machinery: its table reads every role from the theme's own palette (`lisp/romacs/romacs-theme-roles.el`), and the only Modus core kept is vivendi, which Rum derives from. **Package-observable**: `custom-available-themes`' answer. Romacs's own colour schemes replace each other: enabling one disables any other enabled (`romacs-theme--replace-stock`), so `rum` and `default` toggle; a third-party colour scheme enabled over the stock theme replaces it, once, and otherwise themes stack as GNU's do; disabling the last gives GNU's faces. The workspace, which has no Custom, declares `default`'s faces as their own specs; `--gnu-lisp` shows GNU's Lisp alone, with no theme. Romacs also ships the palettes of Omarchy's themes as `omarchy-NAME` (`etc/themes`, generated by `tools/import-omarchy-palettes`; their families are on the theme symbols before they load, so `theme-choose-variant` finds an unloaded variant) and `system`, the theme of the palette file `romacs-theme-system-file` names, which signals a `user-error` while that option is unset: `custom-available-themes` lists those, the ported schemes and `newcomers-presets`.
