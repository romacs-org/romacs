| VM2-CT2 | Char-table index rejection is unstructured | GNU signals `(wrong-type-argument characterp N)` from `aref` AND `aset` for any index below 0 or at/above `#x400000`, carrying the predicate and the offending value; `#x3FFFFF` is valid and yields nil. Verified on live GNU Emacs 32.0.50: `(condition-case e (aref (make-char-table 'test) -1) (error e))` => `(wrong-type-argument characterp -1)`. | VM2 raises an unstructured range error from `char_table.rs:15` (`get`) and `:20` (`set`), which test `index >= LEN` and return `"index out of range"`. There is no `characterp` check, so the condition symbol, the predicate and the offending value are all absent. A negative index cannot arrive as a negative number at all, because the slot index is `usize`. | The dense keymap char-table (VM2-CT1) implemented only the indexing it needed for `make-keymap`, and bounds rejection was written as an internal guard rather than as GNU's Lisp-visible type error. Observable by any `condition-case` dispatching on `wrong-type-argument`, and by anything reading `(cadr e)` to report which value was rejected. Found by the integration reviewer after VM2-CT1 merged; recorded here rather than left implicit, per the rule that every Lisp-visible break gets a row. |
