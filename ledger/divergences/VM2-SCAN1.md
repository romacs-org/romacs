| VM2-SCAN1 | syntax.c scanning engine | `src/syntax.c` `forw_comment`, `back_comment`, `Fforward_comment`, `scan_lists`, `scan_sexps_forward` read each character's syntax through gl_state, whose interval bookkeeping can lag the scan position in rare backward-then-forward property cases; `parse_sexp_propertize` and `find_defun_start` call Lisp mid-scan | `crates/romacs-vm/src/syntax_scan.rs` transcribes the scans with every comment style, nesting, fence, escape and prefix flag, and looks syntax up at the exact position (GNU's intent). Where GNU calls `internal--syntax-propertize` or `syntax-ppss`, the T2 primitive stops, performs the call, and reruns the deterministic scan from the first run's start, coerced positions, initial parse state and variables, replaying the syntax the stopped run read, so calls, arguments, order, results, GNU's three error checks and the find_start cache match. The scan's variables (`parse-sexp-ignore-comments`, `comment-end-can-be-escaped`, `open-paren-in-column-0-is-defun-start`, `comment-use-syntax-ppss`, `parse-sexp-lookup-properties`) are read when it starts; GNU reads all but `multibyte-syntax-as-symbol` live, so a `syntax-propertize` function that changes one mid-scan affects later positions there and none here. Each run reads the buffer's flat text, so a scan after an edit first flattens the buffer, and N propertize calls cost N scan prefixes.
