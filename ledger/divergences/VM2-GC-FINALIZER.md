## VM2 explicit garbage collection

| # | Mechanism | GNU | Romacs | Why |
|---|---|---|---|---|
| VM2-GC-FINALIZER | When finalizers run | `make-finalizer` (`alloc.c:3978`) makes an object whose function runs once after the collection that finds it unreachable: `garbage_collect` dooms the unmarked finalizers after the roots and before weak tables (`queue_doomed_finalizers`), keeps them and their functions, and calls each before it returns, with `inhibit-quit` t and a signal logged to *Messages* as `finalizer failed: ...` (`run_finalizers`, `alloc.c:3960`), automatic collections included, wherever they are reached: inside `unbind_to`'s cleanups and unbinding watchers too, and nested inside a running finalizer. Its conservative stack scan may keep a finalizer a C frame still mentions. | The collector dooms finalizers at GNU's point in marking and keeps them, with their functions, until they run (`crates/romacs-vm/src/gc.rs`). `romacs--run-finalizers` (`rlisp/vm/prelude.el`) calls them as `run_finalizers` does, and then `post-gc-hook`. An explicit `garbage-collect` runs them before it returns, as GNU's, inside a cleanup or a running finalizer too. After any other collection they wait, pending, for the next safe point, whichever collection doomed them: an engine's ordinary poll (a back-jump or a Lisp function entry, the first after a handler's landing included); the end of an embedder's request or of `Vm::execute`, before its result is handed back; an isolate job's end, before it replies; a wait for input (`romacs--timer-check-idle`, a prompt's `romacs--collect-idle`). Every one of them asks one gate (`Vm::safe_runner`, `romacs--safepoint`): no escape is being unwound and no cleanup is running in any engine, and no run is in progress. So none runs between an unwinder and its cleanup, inside a cleanup, in a watcher an unbinding runs, or nested inside a running finalizer or hook. A finalizer doomed while a long cleanup runs, and what only it reaches, waits for that cleanup's end. A finalizer, or a weak table's entry, that only a register of a running frame still holds survives until that register is overwritten or the frame returns: registers carry no liveness, so every register of a live activation is a root, dead ones and ones not yet written included. Registers above an engine's innermost activation are not: each register file is traced only to its engine's top, and a collection clears what lies above it. A child forked from a zygote drops the finalizers it inherits, each running once, in the zygote; the `post-gc-hook` it inherits runs for its own collections. | GNU's place lets a finalizer's escape abandon a cleanup before it begins or halfway through, and start a second run inside a long finalizer; Romacs keeps automatic Lisp off the unwinding path instead. Timing only: GNU's run before `garbage_collect` returns, ours at the next safe point, and nothing in gnu-lisp/, GNU's test/ or rlisp/ depends on where. A dead or not-yet-written register is a separate difference, visible from Lisp: in a `let` or function body that discards a new finalizer and then calls `garbage-collect`, pinned GNU runs the finalizer there, from source and from byte code; Romacs runs it once the frame returns. Weak entries show the same: a frame collecting with registers it has not yet written can hold a key a callee left there (`ft-weak-*-removal-wide` in `test/src/fns-weak-tests.el`, expected to fail), where GNU's conservative stack keeps 0 to 2 such entries depending on the shape. Closing it needs per-register liveness (stack maps over the compiled code), planned with the execution core's redesign; clearing registers at scope exit would be a second mechanism for the same job. A job's memory budget is enforced outside the job (VM2-ISOLATE-MEMORY), so nothing of it runs in the job's Lisp. An interrupt naming a job is taken only while the job's claim, a marker above its handler's entry (`romacs--isolate-claim`), stands, and waits while finalizers or `post-gc-hook` run, so it always becomes the job's reply. A caught host panic pops the bindings and handlers made since, without their watchers, and runs no cleanup; what they owned (the hook's run, `inhibit-quit`, a job's claim) ends with them. Tests: `crates/romacs-vm/tests/garbage_collect.rs` (GNU-compared where GNU agrees), `tests/isolate_zygotes.rs`, the panic cases in `src/threaded_reader_gc_tests.rs`, `finalizer-object-type` in GNU's alloc-tests.el. | <!-- symbols: make-finalizer, garbage-collect -->
