## Observable by a user: workspace file coding

| # | Scope | GNU | VM2 | Reason / evidence |
|---|---|---|---|---|
| VM2-WORKSPACE-CODING | File coding in the default workspace (no loadup) | GNU's image has all of mule-conf.el and the language environments; `set-locale-environment` for a UTF-8 locale on GNU/Linux puts `utf-8` first in `coding-system-priority-list` and makes the default `buffer-file-coding-system` and `default-file-name-coding-system` `utf-8-unix`. It also evaluates mule.el's auto-coding machinery (`auto-coding-alist`, `auto-coding-regexp-alist`, `auto-coding-functions` with `sgml-xml-auto-coding-function` and `sgml-html-meta-auto-coding-function`, `find-auto-coding`, `set-auto-coding`, `coding-system-get`, `coding-system-category`, `coding-system-equal`) and its `(setq set-auto-coding-function ...)`, and mule-cmds.el's `select-safe-coding-system` with `find-coding-systems-region`, `sort-coding-systems`, `coding-system-change-eol-conversion`, `coding-system-change-text-conversion`, `get-language-info` (`language-info-alist` nil, `current-language-environment` "English") and its `(setq select-safe-coding-system-function ...)`, together with the helpers they call from files.el (`set-auto-mode-1`, `inhibit-local-variables-p`, `file-name-sans-versions`, `find-file-literally`), subr.el (`caar`, `ignore-errors`, `string-match-p`, `ensure-list`), byte-run.el (`defsubst` and its `eval-and-compile`, `function-put`, `byte-run--set-speed`) and mule-util.el (`with-coding-priority`). `rlisp/romacs-coding.el` then sets GNU's UTF-8-locale result restricted to those systems: priority `utf-8 iso-latin-1 raw-text utf-8-auto utf-8-with-signature undecided` and the `utf-8-unix` defaults; it assumes a UTF-8 locale. Its one adaptation replaces the question: the workspace cannot show GNU's *Warning* explanation (temp-buffer display, help buttons, fill), so `select-safe-coding-system-interactively` signals `romacs-unsafe-coding` with the unsafe defaults and the safe systems GNU would offer; `write-region` has not opened the file, which keeps its bytes, and the buffer stays modified. The workspace save (`romacs-gui-write-visited-buffer`, `rlisp/romacs-startup.el`) keeps `last-coding-system-used` as GNU's `basic-save-buffer-1` and `-2` do. No other coding system is defined (ISO-2022, UTF-16, CJK, other ISO-8859 sets), and `file-coding-system-alist` stays nil. | UTF-8 (LF and CRLF), ASCII and Latin-1 files (with or without a cookie, agreeing with the bytes or not) and a UTF-8 file with a BOM visit, edit and save as pinned GNU does: decoded text, `last-coding-system-used`, `buffer-file-coding-system` and bytes on disk, including λ typed into a Latin-1 file (saved as UTF-8) and text typed before a BOM (kept after the signature) (`crates/romacs-vm-gui/src/command.rs` `coding_journey_visits_edits_and_saves_as_pinned_gnu`); (2) a cookie or signature naming a coding system the workspace does not define (e.g. `coding: euc-jp`, a UTF-16 BOM) is ignored by the visit, which detection decides, and saving then signals `void-function display-warning` before writing where GNU warns and asks `Really proceed with writing?` (warnings.el is absent);
