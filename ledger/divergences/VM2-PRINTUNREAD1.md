## Observable by a package

| # | mechanism | GNU | romacs | why |
|---|---|---|---|---|
| VM2-PRINTUNREAD1 | When `print-unreadable-function` is called | `print_vectorlike_unreadable` (`src/print.c:1700`) calls it as the print reaches each unreadable object (a buffer, marker, window, frame, process, overlay, obarray, primitive...), with the variable bound to nil, and prints its string, nothing, or the object as usual. A print the function itself makes shares the outer print's ` prin1` buffer: in pinned GNU, `(let ((print-unreadable-function (lambda (_o _e) (prin1-to-string "inner") 'skip))) (prin1-to-string (list 1 (make-marker) 2)))` is `"(1 ner\" 2)"` | `prin1`, `princ`, `print` and `prin1-to-string` first list the unreadable objects their print meets (a Rust pass that runs no Lisp), call the function on each in that order (`romacs--print-unreadable`, `rlisp/vm/prelude.el`, so a `throw` from it leaves the print as in GNU), then print with the answers. The calls see neither the print's OVERRIDES bound (GNU's see, say, `print-length` as `(length . 3)` sets it) nor, under `print-circle` with `print-continuous-numbering`, the labels the print is assigning in `print-number-table`. The function's own prints never leak into the outer one: the example is `"(1  2)"`. `format`'s `%S` and `%s` print unreadable objects as usual, and a print that cannot call Lisp (an error message, `%S` of a propertied string) refuses when it meets one while the function is set | **Package-observable, rarely:** the function runs before any of the print's output is emitted, so a stream callback or buffer stream sees the output after all the calls rather than interleaved with them; `readablep`, `cl-print` and help's value printing are unaffected (`tests/journey_primitives.rs`, GNU's `print-tests.el`) | <!-- symbols: print-unreadable-function, readablep, prin1, prin1-to-string, princ, print -->
