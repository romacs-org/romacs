## World snapshots

| # | Mechanism | GNU | Romacs | Boundary |
|---|---|---|---|---|
| VM2-WORLD3 | The libraries a user's init loads, in a VM restored from a world | GNU dumps only its own preloaded Lisp; every library the init requires loads from source or bytecode in each session, and its load-time `defcustom`, `defvar` and `defconst` forms evaluate in that process (`executable-find`, `locate-user-emacs-file`, `(getenv ...)`). | A live `--loadup` launch that loads the init restores the init's layer when the store holds one (`romacs_vm::world::layer`, `crates/romacs-vm-gui/src/world.rs`): the base world plus the libraries the init's recorded plan loads, replayed after the chain under each entry's recorded `load-path`. The plan is the `require` and autoload calls the init itself issued, recorded while it ran; a launch without a current layer boots from the base world, records the plan again and builds the layer ahead of the next launch. A layer's definition form that reads a per-process fact is kept and evaluated again at restore (`romacs--world-reseed-forms`: a `defcustom` through `custom-reevaluate-setting`, the others by their value form), as GNU's delayed init re-evaluates its dumped options; a definition a refused effect cuts short (a `make-directory`) is deferred whole. Any other form's such read, an effect, a signal or a timer left behind refuses its entry, which then loads from source as before. The startup function runs again in the builder after the libraries, as a restored process runs it after them, and must compute what it computed before them. | **Package-observable** in four ways. A library's load-time code sees the standard value of a variable the init sets before requiring it, since the layer loaded the library first (the init's own `setq` still applies after). A hook function a library adds when it loads precedes, in `add-hook`'s order, the ones the init adds, where a source session has the init's first (`kill-emacs-hook`: the init's savers run before org-persist's). A library's load-time code runs with the chain's initial terminal, not the session's display: `window-system` and `display-graphic-p` answer nil there, where a source session's library finds the pgtk frame (`noninteractive` is nil in both). A `require` the init issues only under a condition that differs between sessions is replayed from the previous session's plan: the layer may hold a library this session's init would not have loaded; the next launch plans afresh. A library edit, a package update, a changed `load-path`, an edited init, another build or another base world rebuilds or bypasses the layer: every file a layer build read is a keyed record of its manifest, the plan's digest and the base world's key are in the layer's key, and the init's content digest is checked at the launch. `ROMACS_WORLD=off` boots from source. | <!-- symbols: require, autoload, custom-reevaluate-setting, load-path -->
