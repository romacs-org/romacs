| VM2-TEXT-ANIMATION | The display animates a block of buffer text itself | GNU shows a buffer's text as it is; an animation rewrites the text from a Lisp timer, one redisplay per frame | `rlisp/romacs-animate.el` keeps each animation's block of a window's cells (rows by columns from a visual row) in `romacs-animate--elements`; every frame the evaluator freezes carries the entries whose window still shows their buffer (`Vm::text_animations`), and the render thread draws exactly the frame's animations, keeping the clock, the motion time and the frames, over its copy of that frame at every draw (`romacs_display_protocol::text_animation`, `render_thread/text_animations.rs`): no Lisp runs and no redisplay happens per frame, and a frame that no longer shows the buffer draws none. The buffer holds a still frame, which Lisp redraws only when the size of a window showing it changes; each cell's colour is the kind's, drawn in a face like the one the evaluator laid the block out in. Every window of the selected frame that shows the buffer has its own animation, whichever is selected or where its point is; the block moves only while Lisp says it may (`rlisp/romacs-animate.el`: shown in the selected frame, the frame focused, not paused, `romacs-animate-motion-p`) and the native window has focus and is not hidden; it stops at once and resumes without catching up. A display on a software rasterizer (every headless harness and GUI test) draws none unless `ROMACS_LAYER_ANIMATION` is 1 (`romacs--display-animates`), so screenshots and parity do not depend on frame timing.
