## Observable by a package

| # | mechanism | GNU | romacs | why |
|---|---|---|---|---|
| VM2-EWCLOAD1 | Compile-time requires of source-loaded GNU Lisp | GNU loads its bundled Lisp as `.elc`, where an `(eval-when-compile (require 'X))` left nothing: X loads only if something else needs it. So eshell's `esh-util.el` (and `term.el`) do not load `ange-ftp` | VM2 loads that Lisp from source and compiles each function when it is defined, so macros from X must exist then: the `require` runs, and X's load-time effects happen. Requiring `esh-util`, as `eshell` and `project-eshell` (`C-x p e`) do, loads `ange-ftp`, which adds `ange-ftp-set-buffer-mode` to `find-file-hook`; it tests each visited name with `posix-string-match` and changes nothing for a local file. Likewise the first source load of `bytecomp.el` and `byte-opt.el` (cc-mode's compile-time requires reach them when a C file is visited) runs their load-time self-compilation blocks, which print `compiling FUNCTION...done` for each function; the `byte-compile` calls themselves return the already compiled functions (VM2-BYTECOMP1). Skipping such requires is unsound while a function body cannot pick up a macro defined after the body was compiled (GNU's evaluator expands it when the call is evaluated; VM2 signals `invalid-function`) | **Package-observable:** `(featurep 'ange-ftp)` and `find-file-hook` differ after eshell loads; visiting behaves as GNU's. File-name completion (`~/` typed in the middle of a path, `~USER`) loads neither tramp nor ange-ftp, as in GNU (`tests/journey_primitives.rs`) | <!-- symbols: eval-when-compile, ange-ftp, find-file-hook, esh-util -->
