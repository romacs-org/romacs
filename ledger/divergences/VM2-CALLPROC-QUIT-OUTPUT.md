## Observable by a package

| # | mechanism | GNU | romacs | why |
|---|---|---|---|---|
| VM2-CALLPROC-QUIT-OUTPUT | The output a quit in `call-process` leaves | callproc.c `call_process`, without DISPLAY, fills a buffer of 16 to 64 KiB with `emacs_read_quit` before it inserts it; a C-g during that fill unwinds from the read, so the bytes of the partly filled buffer are dropped and only the blocks inserted before it stay in the buffer. With DISPLAY it inserts after each read (`display_on_the_fly`, callproc.c ~803) until a read settles the coding system's detection (~859): it then deletes what it displayed, stops displaying on the fly and carries those bytes into the next fill, which a quit drops as well | `call-process` keeps every byte it read before the quit, DISPLAY or not: the wait ends with the quit beside the bytes (`prim/leaf/call_process_wait.rs` `call_process_wait`), `romacs--call-process-run` returns `(quit . BYTES)`, and `call-process` inserts them, decoded as any output, before it signals the quit (`lisp/vm/subprocess.el`) | Keeping all a command wrote before C-g loses nothing GNU would have kept, and a package sees at most more of the child's output, never less | <!-- symbols: call-process, call-process-region -->
