## Observable by a package

| # | mechanism | GNU | romacs | why |
|---|---|---|---|---|
| VM2-FILEIO2 | GUI open and save commands | `romacs FILE` and the desktop entry's `%F` visit FILE with `find-file` (startup.el `command-line-1`, files.el); GNU `find-buffer-visiting` checks expanded name, truename and revalidated file identifier. `C-x C-s` runs `save-buffer`, which makes backups, runs save hooks, checks visited modtime, routes conflicts through `ask-user-about-supersession-threat`, and clears modified state. GNU `kill-buffer` runs query functions, aborts on nil, runs the kill hook, detaches the buffer and repairs windows. Modification state compares SAVE_MODIFF with MODIFF, not text; real undo may explicitly restore clean via saved-modtime undo metadata | While GNU files.el is unavailable the GUI uses explicitly named romacs adapters over native primitives. `romacs-gui-visit-file` uses native exact-name, saved-truename and revalidated device/inode identity, reusing hardlinks, symlinks, equivalent paths and direct Lisp native visits without losing edits. Failed GUI visits are cleared/killed rather than adopted as successful empty buffers. Startup consumes `+LINE[:COLUMN]` and `--`. Save is a no-op when native `buffer-modified-p` is nil; otherwise native stat-only `verify-visited-file-modtime` checks nanosecond time and recorded size, without disk-content reads. Conflicts install future-key y/n/C-g overwrite confirmation: y writes and refreshes metadata; n/C-g preserve both versions. Same modtime/size content changes are deliberately not interrogated, matching GNU. Removed files also prompt here, unlike GNU recreation policy. A dynamic mode-line `*`/`-` reflects native modification counters, including inverse edits to saved bytes. Existing GNU mode-line-format is preserved. In the workspace without GNU Lisp (with it, C-x k is GNU's `kill-buffer`, which asks before killing a modified file buffer), C-x k now truly kills the captured buffer after y (clean buffers immediately), runs native query/hook lifecycle and honors vetoes; dead identities remain buffer objects, leave registries, detach markers/overlays and are replaced in windows. C-x C-c/native close confirm modified GUI visits, including hidden visits. Non-answer/prefix input or buffer switch cancels pending consent instead of GNU modal reprompting; GUI confirmation is an asynchronous adapter, not GNU userlock.el. Native kill lacks process/indirect/autosave/lock/update-hook lifecycle and GNU window-history policy (see crates/romacs-vm/GNU-DIVERGENCES.md). Native alias lookup is named `romacs-find-buffer-visiting`, not full GNU `find-buffer-visiting` predicate/handler support; noncurrent anonymous visits are not enumerated. No native undo record/replay, backups or save hooks; the save reports the write's GNU `Wrote` message. GNU display-column customization/ctl-arrow/C1 controls are not fully implemented for startup positions | **User-observable and package-observable**: ordinary supersession, confirmed/vetoed kill, hardlink reuse and counter-based modified indication are implemented. Packages can call native get-file-buffer, modified-state and kill primitives, but do not acquire GNU save-buffer/find-file/userlock/undo Lisp through these adapters. Exact timestamp, callback-list mutation, omitted kill subsystems and alias lookup limits remain observable. A reverse edit remains modified; a real GNU undo-to-save may become clean and cannot yet run in VM2. FIFO no-reader/deadline behavior remains a deliberate divergence described in VM2-FILEIO1. | <!-- symbols: find-file, save-buffer, get-file-buffer, kill-buffer, buffer-modified-p, buffer-modified-tick, buffer-chars-modified-tick -->
