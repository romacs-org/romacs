## Observable by a package

| # | mechanism | GNU | romacs | why |
|---|---|---|---|---|
| SERVER2 | Server-first lifetime | GNU's `--daemon` starts with no frame on a terminal of its own; `emacsclient -c` makes frames, and the last one's deletion keeps the daemon; a plain `emacs` is a separate process | `romacs --server NAME` (the launcher's default, `tools/romacs`) connects to server NAME's native socket (`$XDG_RUNTIME_DIR/romacs/NAME/server.sock`, the MCP endpoint with the client methods `romacs/frame`, `romacs/eval`, `romacs/stop`), starting it as the transient user unit `romacs-server-NAME` (else detached with `setsid`) when none listens. The server (`--serve NAME`) is the GUI session with no window until a client asks; its one top-level frame is the host frame, whose window is made on request (`romacs--native-window`), and closing it (or `C-x C-c`, `save-buffers-kill-terminal`, after offering to save) keeps the session unless `romacs-server-exit-with-last-frame`; the next client shows it again. A second client while it shows asks for the focus and visits its files there: one window, not one per client (several top-level frames are VM2-WIN-SUBSTRATE's). It also runs server.el on `$XDG_RUNTIME_DIR/emacs/NAME` (`romacs-server-gnu-socket`). A native client waiting on files is kept out of `server-clients` in a buffer-to-waiters index; `server-edit`, `server-done` and `kill-buffer` finish its buffers with GNU's save question and recursion guard. A client with no files on an empty session shows the *Romacs* landing where GNU's shows *scratch*, unless `initial-buffer-choice` or `inhibit-startup-screen` is set | **Visible to the user** (one process and one window across launches); Lisp sees `romacs-server-name` | `crates/romacs-vm-gui/harness/server_live.py` (lifecycle, waiters, landing, unit, probe, daemon) | <!-- symbols: romacs-server-start, romacs-server-name, romacs-server-exit-with-last-frame, romacs-server-gnu-socket, romacs--native-window, server-edit, server-done, save-buffers-kill-terminal -->
